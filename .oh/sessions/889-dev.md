# Dev Pipeline -- Per-file churn and churn x complexity hotspots

Salvage item 2 of 6 from the ripwire review (Apache-2.0; ideas only).

## Phase 1: Problem Statement (issue #889)

RNA knows how central a symbol is (PageRank) and how branchy it is (`cyclomatic`), but not whether the code *moves*. No churn signal exists. Separately, `repo_map`'s "Hotspot files" ranks by definition count -- a size measure printed under a risk label.

Duplicate issue #888 was closed: it asserted complexity is computed but never rendered. That is false on current main (see Phase 2 findings). Its useful contribution, the pointer to guardrail `computed-but-not-delivered`, is carried into #889.

## Phase 2: Verified findings (established before designing)

1. **Cyclomatic complexity already exists end to end.** Computed at `src/extract/generic.rs:526` (`metadata["cyclomatic"] = 1 + branches`, branch kinds via `LangConfig`, so the no-language-conditionals guardrail is already satisfied). Persisted through `src/graph/store.rs` and `src/server/store/{batch,load,metadata_keys}.rs`. **Rendered** in `src/server/helpers.rs:370` (` cc:{}` on compact rows) and `:490` (`\n  Complexity: {}` on detailed rows). Used for filter/sort only in `src/service/search.rs:493` (`min_complexity`) and `:670` (`sort_by_complexity`). Tests: `test_cyclomatic_complexity_linear_function`, `test_cyclomatic_complexity_with_branches`.
   => Do not touch complexity extraction, persistence, or rendering.

2. **Churn does not exist.** `grep -rn churn src` is empty.

3. **Churn is already computed and thrown away.** `mine_cochanges` (`src/git/cochange.rs`) builds `file_changes: HashMap<PathBuf, u32>` -- "total commits touching a given file (within the mined window)" -- uses it only as the confidence denominator via `CoChangePair.changes_a/changes_b`, and drops it: `CoChangeMiningResult { pairs, head_sha, commits_walked }` at `:223`. This is textbook `computed-but-not-delivered`.

4. **Single history walk already bounded.** `CoChangeConfig` (`src/scanner.rs:156`): `max_commits` 500, `max_age_days` 365, `max_files_per_commit`. First-parent revwalk, hard `max_commits` ceiling on every walk including watermark walks (fixed in 2c80d32), watermark in scan state, non-git degradation reported in `src/service/roots.rs`.

5. **Hotspots computation** is `src/service/repomap.rs:263-299`: counts nodes per (root, file) excluding Import/Module/PrMerge/Field and `root == "external"`, sorts desc, truncates to 10, renders "- `file` -- N definitions" under `## Hotspot files`.

6. **Anchor nodes exist per file already**: `NodeKind::Other("file")` anchors (`file_anchor_node_id`) are created for files appearing in co-change pairs -- a natural carrier for churn, but only covers paired files. Files with churn but no qualifying pair would need an anchor too, or churn stored in a side map like `cochange_stats`.

## Phase 2: Chosen approach

**Reframe, minimal surface**: surface what the existing walk already computes; add no second git traversal.

- `CoChangeMiningResult` gains `file_changes: HashMap<PathBuf, u32>` (already in scope at the return site -- a move, not a recomputation). `mine_and_build` threads it out.
- Persist churn as metadata on the per-file anchor node (`churn` key), extending anchor creation to cover every file with a non-zero change count in the window, not only paired files. Keeps churn in the existing node/metadata persistence path (no new column, no edges-table change). Bump `SCHEMA_VERSION` only if the persisted shape actually changes.
- Hotspots: rank by `churn x aggregate_complexity` per file, where aggregate complexity is the sum of `cyclomatic` over that file's non-excluded nodes. Render the basis explicitly, e.g. "ranked by churn x complexity (commits in window x summed cyclomatic)", and show the components so the number is auditable. Files missing churn (non-git root, or outside the window) fall back to a stated basis rather than a silent zero.
- Render churn wherever complexity is rendered: `helpers.rs:370` compact (` churn:{}`) and `:490` detailed (`\n  Churn: {}`).
- Non-git roots: reuse the `roots.rs` availability precedent, extending the existing "Co-change: not available (no .git)" line to cover churn.

Rejected: a separate churn miner (violates the single-walk objective and doubles scan cost); a new LanceDB column for churn (node metadata already persists and is the lighter change); leaving hotspots as-is and adding a second section (keeps a mislabelled section in the output).

## Phase 3: Execute

Rebased onto `origin/884-cochange-graph` (`2c80d32`, `51ce321`) before starting; dropped an empty `wip` placeholder commit that predated the rebase (`git reset --soft`, no content lost).

Implemented per the Phase 2 chosen approach, no deviation:

1. `CoChangeMiningResult` gains `file_changes: HashMap<PathBuf, u32>` (moved from the local var already built inside `mine_cochanges`, not recomputed). `MineAndBuildResult` extended to a 5-tuple carrying it through `mine_and_build`. Both call sites in `src/server/graph.rs` (full-scan and incremental) updated; churn itself only needs to reach `build_file_anchor_nodes`, so the tuple's 5th element is `_file_changes` (unused) at both call sites.
2. `build_file_anchor_nodes` extended to accept `file_changes` and create/stamp an anchor for every file with a non-zero mined-window count, not just paired files (`churn` metadata key, string-encoded like `cyclomatic`). No `SCHEMA_VERSION` bump: `churn` is not in `metadata_keys::TYPED_KEYS`, so it flows through the existing `generic_metadata_json` fallback column that already round-trips arbitrary untyped metadata keys -- confirmed by reading `src/server/store/batch.rs`/`load.rs` before implementing, per the "no new column" constraint in the chosen approach.
3. `src/service/repomap.rs` hotspots block rewritten: per-(root,file) aggregate complexity (sum of `cyclomatic` over non-excluded nodes, `or_default()` so zero-complexity files still appear) x per-file churn (read from `NodeKind::Other("file")` anchor metadata). Churn availability is explicit: `Unavailable("root not mined for co-change/churn")` when the file's root isn't `RootConfig::code_project(ctx.repo_root).slug()` (mining only ever runs against the primary root), `Unavailable("no .git")` when `git2::Repository::open(ctx.repo_root)` fails, else `Known(churn)` (0 is a real in-window count, not "unknown"). Rendered as `churn N x complexity M = SCORE` or `churn: not available (reason); complexity M`. Section header now states the ranking basis. Ties (including all-zero-score) broken deterministically by file then root.
4. Churn rendered in `src/server/helpers.rs` alongside cyclomatic in both the compact (` churn:{}`) and detailed (`\n  Churn: {}`) branches of `format_node_entry_with_root` -- the same function that already renders `cyclomatic`/`Complexity`. Verified end-to-end this is reached via `search --node <id>` (not the CLI `graph` subcommand, which uses an entirely separate hand-rolled formatter in `src/service/graph.rs` that never rendered complexity either -- pre-existing, out of scope).
5. `src/service/roots.rs`: extended the existing "Co-change: not available (no .git)" line to also state churn unavailability for the same reason, mirroring the existing non-git-root precedent.
6. Docs: README (two spots) and AGENTS.md updated for the ranking redefinition. `src/viewer.html`'s JS fallback graph parser regex updated to match the new hotspot line format (`churn N x complexity M = SCORE` or `churn: not available (...); complexity M`) instead of the old `N definitions`.

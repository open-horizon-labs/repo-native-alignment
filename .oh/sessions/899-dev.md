## Hunk-intersection design

`resolve_changed_file_entries(repo_root, scope)`:
1. Builds the git2 diff for the scope with `context_lines(0)` -- this is the
   key decision: with default context (3 lines), a hunk's `new_start`/
   `new_lines` span would bleed 3 lines into neighboring untouched symbols,
   which is exactly the "every symbol in the file" failure mode the issue
   warns about. Zero context makes the hunk header itself equal to the
   changed lines.
2. Runs `DiffFindOptions { renames: true, copies: true }` via `find_similar`,
   matching `changed_file_plan.rs`'s approach (not reusing its code, since
   that module is `server`-private and its types don't fit).
3. Builds one `ChangedFileEntry` per delta (kind, old/new path), keyed by new
   path (or old path for pure deletions) in two lookup maps.
4. Runs `diff.foreach` with a hunk callback (not a line callback -- the issue
   specifically calls for hunk callbacks); for each hunk, records
   `(new_start, new_start + new_lines - 1)` as an inclusive new-side range.
   Pure-deletion hunks (`new_lines() == 0`) get a single-line anchor at the
   boundary so a symbol adjacent to a deletion isn't silently dropped.
5. Callers select changed symbols as: added/untracked files -> every symbol
   in the file; other files -> nodes whose `line_start..=line_end` intersects
   any hunk range; deleted files -> nodes still in the graph, listed
   separately and flagged, never merged into "changed symbols".

## Friction / notes for next time

- `src/server/changed_file_plan.rs` being `server`-private forced a small
  duplicated `ChangeFileKind` enum rather than a shared type. If a third
  consumer needs file-kind classification, it's worth promoting one shared
  type to a neutral module (e.g. `src/git/mod.rs`) instead of a third parallel
  definition.
- `note_identity`/`note_excerpt` in `server::helpers` were private with no
  reason beyond "not needed elsewhere yet" -- bumped to `pub(crate)`. Worth
  checking whether other server-private helpers will need the same treatment
  as more `search` modes compose existing rendering.

# Issue #827: Hermetic RNA-first Sonnet selector

## Aim

Experiment operators can attribute paired A/T differences to the RNA-first
treatment rather than network or cross-arm leakage while Sonnet retains the
standard Bash, Edit, Read, Write, Glob, and Grep interface.

The mechanism is a split execution plane with independently audited evidence.
The immediate signal is a symmetric no-spend escape matrix; the later signal is
four verifier-clean episodes whose evaluators were authorized only after ledger
audit.

## Problem Space

The provider parent needs network and trusted harness state, while model-issued
tools must see only their own checkout, private temporary state, and declared
toolchain. Hooks alone cannot enforce nested interpreter, link, or syscall
boundaries. Blocking an operation without recording that it was attempted is
also insufficient because any forbidden attempt is registered nonadherence.

Hard constraints:

- identical ordinary tool surface and isolation for A and T;
- model tools have no network or sibling/evidence/credential visibility;
- any forbidden attempt terminates before evaluation;
- stable IDs come only from exact final injected bytes;
- every RNA entry point revalidates live checkout/cache identity;
- missing, malformed, inconsistent, or synthetic-zero usage fails closed;
- a complete actor-ledger audit precedes evaluator authorization.

## Problem Statement

The selector needs an unforgeable separation between provider/control-plane
privileges and model-tool privileges because Claude's parent needs provider
transport while model-issued operations must never inherit it or trusted
experiment state.

This reframes #827 from command denylisting to capability separation plus
independently recomputed authorization.

## Solution Space

Candidates considered:

1. hook/path/string denylisting only — rejected because nested interpreters,
   links, syscall-level network, and hook failure bypass it;
2. outer filesystem confinement plus an offline Bash gateway — selected as the
   smallest design supported by local feasibility;
3. whole Claude runtime container plus a separate provider relay — viable but
   substantially larger;
4. per-episode macOS VM — strong but costly to provision and verify;
5. privileged Endpoint Security enforcement — strong but requires entitlements
   and a host daemon.

Selected boundary:

- Claude parent: per-episode filesystem confinement with provider transport;
- native file tools: unchanged model surface, hook validation, and OS
  confinement;
- Bash: statically denied unless the exact PreToolUse hook replaces it with an
  immutable single-use request for a digest-pinned offline worker;
- RNA: separate trusted broker with pre/post live identity validation;
- evidence/evaluation: monotonic hash-chained ledger and a one-use evaluator
  authorization minted only by an independent auditor.

The exact production launch stack must pass the no-spend escape matrix before
registration or model calls. A mere permission error or absent network route
without a structured enforcement event is a NO-GO.

## Execution Plan

1. Adapt the #825 harness into a #827-specific frozen registration without
   reusing selected cases or outcome artifacts.
2. Implement the symmetric isolation supervisor, single-use Bash gateway,
   trusted RNA broker, strict usage parser, ledger auditor, and evaluator gate.
3. Run the bounded synthetic no-spend matrix against the production launch
   stack.
4. Freeze and publish all hashes, exclusions, fresh deterministic cases, and
   schedule.
5. Only then run the four fresh 1,200-second/$6 episodes and permitted official
   evaluators.
6. Independently verify, apply the unchanged selection rule, and ship.

## Pre-spend findings

- Exact macOS qualification proved that a restrictive Seatbelt cannot be
  applied beneath Claude's existing restrictive outer Seatbelt. The retained
  `success6` attempt failed before RNA exec with `sandbox_apply` return code 71.
  The registered host-broker boundary is therefore required rather than direct
  nested execution.
- Exact Claude CLI fake-provider traffic includes one auxiliary session-title
  request outside the agent transcript. Whole-invocation `modelUsage` includes
  those tokens and remains authoritative; transcript usage is a strict subset,
  and its nonnegative difference is retained as auxiliary CLI usage.
- The model cap is 1,200 seconds and $6 for each of the four fresh episodes.
  The cap covers the complete invocation, including auxiliary CLI traffic.

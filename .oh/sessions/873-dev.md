# 873: LSP Pass 1 quadratic work / body clones -> OOM on large repos

## Phase 1: Problem statement

Issue: https://github.com/open-horizon-labs/repo-native-alignment/issues/873

Full-repo LSP enrichment on a 7,390-file repo (518,671 nodes; 193,777 Rust-matching nodes; ~146k Pass 1 work items) reached ~20 GiB RSS and was OOM-killed. Root causes (all verified against HEAD):

1. `passes.rs` `enrich_function_node` (~939): per work item, `matching_owned.iter().collect()` + fresh `HashMap<(PathBuf,String),Vec<NodeId>>` over ALL nodes -> ~2.8e10 hash inserts; 64 concurrent throwaway maps.
2. Same per-item rebuild in `enrich_trait_node` (~1118) and `enrich_type_references` (~1167).
3. `LspPass1WorkItem.node: Node` full clone (with body) per item.
4. `mod.rs enrich()` (~2361) clones matching nodes twice more (`matching_nodes_owned`, `refs_by_file_shared`) with bodies. Pass 1 never reads `.body`.

Follow-ups (out of scope, tracked as checklist items on #873): graph_state clones in `server/enrichment.rs`; nested body duplication in `extract/generic.rs:498`.

## Phase 2: Solution space

PR: https://github.com/open-horizon-labs/repo-native-alignment/pull/874

| Option | Level | Verdict |
|---|---|---|
| A. `Pass1SymbolIndex` of body-stripped Node clones + `by_file`/`by_file_name`, work items hold `usize` | Local Optimum | **Selected** |
| B. Slim `Pass1Symbol` struct with precomputed LSP position | Local Optimum | More churn; `find_enclosing_symbol` + 5 tests need generic/duplicate |
| C. A + per-file sorted intervals/binary search | Local Optimum+ | Unnecessary; per-file lists are small; tie-break risk |
| D. `enrichment.rs` passes `Arc<Vec<Node>>` so Pass 1 clones nothing | Reframe | Right long-term; is the filed follow-up; alone doesn't remove quadratic maps |

Selected A deliberately: no new locks/coordination, edge-identity constraint, D already filed as follow-up.

### Behavioural subtleties that MUST be preserved (edge-for-edge identical)
1. Own node IS in the maps today; self-edges are removed post-resolution (`referrer == node.id` ~913/1194; `caller.name == node.id.name && caller.file == node.id.file` ~992/1078, not kind-aware). Index must include own node; keep post-filters untouched.
2. `min_by_key` first-minimum tie-break depends on `matching_nodes` order. `by_file` must push indices ascending; never sort.
3. No kind pre-filtering in the index: `enrich_type_references` lets `find_enclosing_symbol` filter; `enrich_trait_node` uses `Impl | Struct` only; `(file,name)` lookup is kind-agnostic. Index holds all matching nodes; each branch filters.
4. `resolve_call_target`: exactly one `(file,name)` hit wins; ambiguous (len!=1) AND missing both fall back to enclosing symbol at the call line. Duplicate NodeIds -> 2 entries -> ambiguous, same as today.
5. Path normalization differs by branch (call hierarchy: strip `file://` + `strip_prefix(root)`, no percent-decoding; references: `uri_to_relative_path`). Do not unify.
6. Only lost behaviour: `find_enclosing_symbol`'s "No nodes match path" debug log won't fire for unknown files. No edge impact.
7. `set_phase`/`finish` read `item.node.id.*`; pass `&Node` alongside. Update test `pass1_diagnostic_snapshot_is_bounded_and_phase_counted` (~1741).
8. `LspPass1WorkItem.id` enumerates *enrichable* nodes, not `matching_nodes`; `node_index` is a separate field.

### Call sites
- `src/extract/lsp/passes.rs`: 170-175 struct; 255-285 diagnostics; 436-590 `run_pass1_references`; 741-841 `run_pass1_work_item`; 868-1074 `enrich_function_node`; 1106-1132 `enrich_trait_node`; 1153-1191 `enrich_type_references`; ~1741 test; new `Pass1SymbolIndex` + tests.
- `src/extract/lsp/mod.rs`: 2361-2382 replace both Arcs with `Arc::new(Pass1SymbolIndex::build(&matching_nodes))`; `matching_nodes: Vec<&Node>` stays for passes 0/2/4/5.
- `src/extract/lsp/transport.rs::find_enclosing_symbol`: unchanged.

## Phase 3: Execute

**Updated:** 2026-09-06
**Status:** complete
**Verdict:** PROCEED

### Pre-flight finding: the plan was partially stale against HEAD
`EndpointLookupIndex` (landed in #800) already replaced the per-item `(file,name)` maps and
linear `find_enclosing_symbol` scans in `enrich_function_node` and `enrich_type_references`.
What remained of #873 at HEAD:
- `enrich_trait_node`: per-item `matching_owned.iter().collect()` + linear scan over all matching nodes.
- `LspPass1WorkItem.node: Node` cloned (with body) per work item, plus the `LspWorkItemSeed` clone.
- `mod.rs enrich()`: `matching_nodes_owned` (bodies; only consumer was the trait branch) and
  `refs_by_file_shared` (ALL graph nodes with bodies, span-sorted; consumers: `EndpointLookupIndex::build`,
  documentSymbol root lookup, barrier item).

### What was built
`src/extract/lsp/passes.rs`
- New `pub(super) struct Pass1SymbolIndex { nodes: Vec<Node>, by_file: HashMap<PathBuf, Vec<usize>>, graph_by_file: HashMap<PathBuf, Vec<Node>> }`,
  `build(matching: &[&Node], graph_nodes: &[Node])`; every stored node is a `body_free_clone`.
  `nodes` keeps matching order; `by_file` indices pushed ascending (never sorted); `graph_by_file` is the
  exact replacement for `refs_by_file_shared` (same stable span sort). Accessors: `node(idx)`,
  `nodes_in_file(&Path)` (order-preserving iterator), `graph_nodes_by_file()`, `file_root(&Path)`.
- `LspPass1WorkItem.node: Node` -> `node_index: usize`. `pass1_work_item_files`,
  `take_pass1_document_symbol_barrier_item`, `execute_pass1_document_symbol_barrier_item` take the index.
- `LspPass1Diagnostics::{set_phase, finish, finish_failed, finish_with_error}` take `&Node` alongside the item.
- `run_pass1_references(.., matching_nodes, symbol_index: &Arc<Pass1SymbolIndex>, ..)`; enrichable-node
  filtering is unchanged but iterates `matching_nodes.iter().enumerate()` so candidates carry their index
  (`admitted_nodes: Vec<(usize, &Node, LspQueryOperation)>`; `sort_document_symbol_candidates` now sorts
  `(usize, &Node)` pairs by the same key). Ledger seeds are built from the body-free index node
  (ledger identity is body-independent; `work_items.rs` test asserts this).
- `run_pass1_work_item`, `enrich_trait_node`, `enrich_document_symbols` take `&Pass1SymbolIndex`.
  Trait branch: `symbol_index.nodes_in_file(&impl_path)` then the unchanged Impl|Struct / line-range
  filters and `min_by_key` first-minimum tie-break. `EndpointLookupIndex::build(symbol_index.graph_nodes_by_file())`.
- Tests updated: `sort_document_symbol_candidates_*`, `pass1_preopen_files_are_deterministic_and_deduplicated`,
  `pass1_diagnostic_snapshot_is_bounded_and_phase_counted`, executor-restart and exhausted-item tests.
  New: `pass1_symbol_index_strips_bodies_but_keeps_everything_else`,
  `pass1_symbol_index_keeps_matching_order_per_file` (includes the trait tie-break),
  `pass1_symbol_index_graph_nodes_are_narrowest_first_and_cover_unscheduled_nodes` (unique vs enclosing
  resolution through `EndpointLookupIndex`, unknown file -> None).

`src/extract/lsp/mod.rs enrich()`: both Arcs replaced by
`let pass1_index = Arc::new(passes::Pass1SymbolIndex::build(&matching_nodes, nodes));`.
`matching_nodes: Vec<&Node>` untouched for the other passes.

### Deviations from the Phase 2 plan
- No `by_file_name` / `resolve_call_target` / `enclosing_symbol` on `Pass1SymbolIndex`: those lookups
  already live in `EndpointLookupIndex` at HEAD; duplicating them would be dead code (clippy -D warnings).
- The index carries the graph-wide per-file map so the AC "single body-free shared index" holds and
  `EndpointLookupIndex` / documentSymbol root lookup receive byte-identical inputs.
- `cargo fmt` under rustfmt 1.97 reformatted 26 unrelated files; reverted, only passes.rs/mod.rs changed.

### Edge-identity argument
Subtleties 1-5, 8 preserved: own node is in the index; per-file iteration order == matching order;
no kind pre-filtering (each branch filters); path normalization untouched; `id` still enumerates
admitted items, `node_index` separate. Subtlety 6 ("No nodes match path" debug log) was already gone at
HEAD via `EndpointLookupIndex`. The only observable change is memory/CPU.

- `cargo clippy --no-default-features -- -D warnings` (CI variant): clean. `cargo clippy --all-targets`
  has ~98 pre-existing `useless_vec` test-code errors in ~30 unrelated files; none in `src/extract/lsp`.
- `cargo test --lib extract::lsp`: 200 passed, 0 failed, 2 ignored.
- Full `cargo test`: lib 2519 passed, 0 failed, 4 ignored; all integration test targets passed (exit 0).

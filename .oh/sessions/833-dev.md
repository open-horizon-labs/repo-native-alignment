# Dev Pipeline — LSP recovery work-identity correctness (continuation)

## Problem

Interrupted or incremental exact-tree LSP recovery must reuse only truly
identical work and remain stable across graph reconstruction. The retained
SymPy no-spend diagnostic showed 26,303 node-ID/operation identities stable
across an identical commit/tree while 9,016 legacy `node_input_hash` values
changed after reconstruction — the old hash mixed reconstruction-time fields
(end line, signature, body) into an identity meant to describe request-time
truth, and it could not detect cross-file config/toolchain drift when the
target node stayed byte-identical.

Gaps found and fixed this session (all four were named in CodeRabbit's review
and in the required technical scope; none were stubs, but the wiring was
incomplete):

1. **Planner-contract rerun vs. tampering** — `LspWorkIdentity` gained
   `planner_contract`, but `identity_disposition` never compared it, so a
   routine `PLANNER_CONTRACT_VERSION` bump fell through to `prior.digest !=
   current.digest` and was misclassified `RejectedTampered`. Added
   `LspRecoveryDisposition::RerunPlannerContract` and an explicit comparison
   before the digest/tamper fallback. Regression:
   `planner_contract_bump_reruns_instead_of_tampering`.
2. **Non-cryptographic integrity wording** — added a comment at the
   `integrity_digest` comparison in `load_store` stating the unkeyed BLAKE3
   digest detects corruption/partial writes, not tampering by a process that
   can already write `.oh/.cache`.
3. **Git-scoped cross-file config test** — the `pyproject.toml` cross-file
   test used a bare `tempdir` with no Git repo, so `non_git_source_snapshot`
   hashed the whole tree and the test would have passed for *any* file edit,
   not specifically the intended cross-file config change. Added a real Git
   init/commit so the test exercises the Git-tree snapshot path production
   uses.
4. **Bounded ignored-input discovery** — `ignored_lsp_influence_identity`
   called `Command::output()` on `git ls-files` with no timeout. Added
   `run_bounded` (spawn + poll `try_wait` against a 5s deadline, kill on
   timeout) and logged spawn failure / timeout / non-zero exit before falling
   back to the full content snapshot. Pattern-scoped enumeration (not a bare
   `--others --ignored` sweep) was already in place and already covered by
   `ignored_descriptor_influence_changes_git_source_snapshot`
   (`build/compile_commands.json`), which still passes.

Also added two `lsp_completeness.rs` regressions CodeRabbit asked for
(`obsolete_nonzero_schema_version_fails_closed`,
`stale_planner_contract_fails_closed`) confirming `select_work_items_for_report`
fails closed on a schema/planner mismatch, not just a nonzero schema. A third
attempted regression (`changed_toolchain_contract_fails_closed_in_report_selection`)
was removed after it exposed a wrong assumption: `select_work_items_for_report`
has no live toolchain/enricher context, so it cannot and does not re-check
`toolchain_contract` against a "current" value — that drift is caught earlier,
at ledger `begin()` time via `identity_disposition`, which already has the
existing `changed_toolchain_contract_replays_with_explainable_disposition`
regression. Forcing a check into the report-selection layer would have been
scope creep into a layer that architecturally doesn't own that comparison.

## Dissent / final review

Self-adversarial pass over the exact diff before commit, reviewed file by
file (`mod.rs`, `passes.rs`, `policy.rs`, `work_items.rs`,
`lsp_completeness.rs`):

- Checked the removed `wildcard_match` fallback in
  `partition_influence_pattern_matches` doesn't silently stop matching a
  slash-free pattern against a full path: `wildcard_match` already treats `*`
  as matching across `/` in the basename candidate, so the removed arm was
  redundant, not a behavior change — confirmed by the retained
  `ignored_descriptor_influence_changes_git_source_snapshot` regression still
  passing.
- Checked `planner_contract` defaulting to `""` via `#[serde(default)]` for
  pre-migration records can't be misread as a match: it can only equal
  `PLANNER_CONTRACT_VERSION` if that constant were ever the empty string,
  which it is not, so old records always take the `RerunPlannerContract` path
  once, then persist the real version — not a `RejectedTampered` mistrigger.
- Checked `find_identifier_boundary`'s advance-by-one-char retry against a
  leading multi-byte identifier match: added regression
  `find_identifier_boundary_finds_valid_match_after_rejected_multibyte_match`
  during this session's review specifically to exercise the retry path after
  a rejected match, not just the reported panic case — passes.
  (`find_identifier_boundary_skips_rejected_multibyte_match_without_panicking`
  was already present.)
- Checked `run_bounded`'s pipe-drain threads can't leak on the timeout path:
  `child.kill()` + `child.wait()` before joining the reader threads ensures
  the pipes reach EOF (the child's fds close on kill), so `.join()` cannot
  block forever waiting for a child that no longer exists.
- Confirmed the one identified process risk — a Git CLI absence or failure
  during `ignored_lsp_influence_identity` broadens to the full non-Git content
  snapshot rather than silently reusing stale evidence — is fail-safe, not
  fail-open: broader identity can only cause spurious reruns, never
  incorrectly-carried work.

No blocking findings. Verdict: ship as continuation work on top of the

# Issue #785 — hermetic frozen-cohort LSP toolchain

## Aim

**Aim:** Benchmark operators can qualify every frozen N=70 checkout's relevant files through RNA's fail-closed LSP readiness gate without host drift or network access.

**Current State:** The completeness gate can identify unsupported, missing, degraded, or stale files, but server discovery still depends on ambient executables and no sealed cohort-derived toolchain proves all required languages offline.

**Desired State:** A fresh macOS arm64 guest installs an exact, licensed, digest-verified toolchain from a prefilled cache, and all 70 frozen checkouts reach complete per-file readiness with reproducible timing and coverage evidence.

### Mechanism

**Change:** Derive the authoritative extension/server inventory from the frozen population, define one closed lock manifest, provision only digest-verified cache entries, verify RNA descriptor parity, and retain offline per-checkout plus aggregate qualification evidence.

**Hypothesis:** Binding inventory, descriptors, cached artifacts, runtime probes, and readiness reports to explicit digests removes both ambient-PATH drift and silent extension exclusion.

**Assumptions:** The frozen checkout sources are obtainable before network isolation; each included extension has a viable arm64-compatible server/runtime; Tart can provide the fresh-guest isolation proof on the qualification host.

### Feedback

**Signal:** The offline qualifier reports the exact 70 frozen identities, zero friction statuses, all locked server probes/capabilities/quiescence checks passing, and an aggregate seal reproducible from retained evidence.

**Timeframe:** At issue qualification, before #786 release-bundle work or any paid benchmark call.

### Guardrails

- Do not remove, ignore, relabel, or weaken inventory entries to make readiness pass.
- Do not depend on Homebrew latest, unpinned package resolution, ambient PATH, or outbound networking after cache acquisition.
- Keep embeddings, reranking, model/API calls, credentials, protocol/population changes, and #786+ scope out of this issue.
- Preserve the repo-native, computed-but-not-delivered, and CI-artifact release rules.

## Problem Statement

**Current framing:** Install the language servers likely needed by a mostly-Python benchmark.

**Reframed as:** Benchmark operators need every relevant file in the exact frozen N=70 population to produce complete, persisted LSP evidence, but server discovery, runtime resolution, descriptor coverage, and qualification are not yet bound to one offline-verifiable artifact set.

**The shift:** From a convenience install script to a cohort-derived supply-chain and delivery proof.

### Constraints

- **Hard:** Frozen population, fail-closed inventory, exact locks/digests/licenses, macOS arm64 offline operation, descriptor parity, zero friction statuses.
- **Soft:** Packaging layout and implementation language of the provision/qualification tools.

### What this framing enables

One closed contract can drive acquisition, cache verification, installation, probes, descriptor drift tests, per-checkout readiness, timing retention, and aggregate sealing.

### What this framing excludes

Ambient package managers, floating versions, partial language support, inventory suppression, or treating successful process startup as readiness.

### Recommendation

**Selected:** Option C — closed cohort-derived toolchain contract

**Level:** Reframe

**Rationale:** The failure mode is not lack of an installer; it is multiple unbound truths. A canonical manifest and deterministic verifier can fail on inventory drift, descriptor mismatch, absent cache entries, executable/package digest changes, missing licenses, failed capabilities, non-quiescence, or non-complete readiness while producing release-manifest-ready evidence.

**Accepted trade-offs:**

- Cache acquisition remains a separate network-enabled phase and must retain provenance/digests.
- Qualification can be expensive because all 70 exact checkouts and every required server must run.
- Any extension without a viable server becomes a visible issue blocker.

### Implementation Notes

- Derive required extensions from checkout bytes and compare them to both locked servers and RNA built-in descriptors.
- Separate acquire, verify/provision, probe, and qualify modes so offline enforcement is testable.
- Retain per-checkout reports, server timing/capability receipts, aggregate report, and digest inventory.
- CI should use fixtures for drift/cache/descriptor tests; macOS arm64 qualification supplies the real Tart evidence.

## Scope Amendment — verified incremental structural-cache reuse

### Problem Space

**Objective:** Preserve verifier-clean structural work across frozen checkouts from
the same upstream repository without allowing stale, mismatched, or partially
persisted LSP evidence to satisfy full target readiness.

| Constraint | Type | Reason |
|---|---|---|
| Full N=70 population and benchmark protocol remain unchanged | hard | Parent preregistration |
| Every successful cache is immutable, retained, and independently verifiable | hard | Reproducibility and downstream #786/#787 consumption |
| Target readiness covers the full target inventory and exact persisted graph | hard | A warm update cannot weaken #784/#785 evidence |
| Schema mismatch rebuilds and never migrates | hard | Disposable benchmark state and fail-closed compatibility |
| No embeddings or reranking in #785 | hard | Assigned to #786 |
| Language/config behavior is descriptor-owned | hard | `no-language-conditionals-in-generic` guardrail |
| Existing checkout only; no worktree/stash/reset/clean | hard | Explicit operator instruction |

The existing foreground `scan --full` path already loads a compatible Lance
cache and performs an incremental update. The missing guarantees are secure
archive transport, producer/schema identity, graph-aware invalidation,
verifier-authorized inherited evidence, strict deletion/reopen proof, and
machine-readable reuse accounting. A Python-only archive injection is
insufficient because current completeness deliberately accepts only work items
from the current scan and current incremental LSP planning covers touched files
without dependency/call closure.

### Solution Space

| Option | Level | Result |
|---|---|---|
| Copy `.oh/.cache` and trust existing incremental scan | band-aid | Rejected: inherited evidence cannot reach READY and cross-file edges can go stale |
| Keep one mutable rolling prewarm | local optimum | Rejected: violates immutable-base and per-success retention requirements |
| Immutable full cache chain with qualifier verification plus Rust inheritance/closure | reframe | Selected: satisfies reuse, auditability, and full target readiness |
| Rebuild every target cold | status quo | Rejected: needless duplicate compute and discards successful structural evidence |

**Selected architecture:**

1. Publish a portable producer/schema identity from the exact RNA binary.
2. Archive each successful structural cache deterministically with an embedded
   canonical core manifest and a sidecar binding the archive SHA-256; publish
   the sidecar last and store its SHA-256 in the case receipt/catalog.
3. Verify and safely extract only regular declared members into a fresh staging
   directory; reject traversal, links, special files, duplicates, tampering,
   truncation, partial publication, and embedding/rerank payloads.
4. Deterministically select the nearest earlier READY archive from the same
   upstream repository. Schema/producer/global-contract mismatch rebuilds cold;
   descriptor-owned configuration/dependency/toolchain differences invalidate
   affected language partitions, with unknown/shared influence rebuilding all.
5. Diff the verified base tree to the target tree with rename detection. Before
   purge, compute a deterministic dependency/call/reference impact closure from
   old and preliminary-new structure; ambiguous or over-bound closure escalates
   to partition rebuild. Execute LSP exactly once for the resulting plan.
6. Compose a fresh target completeness generation from current execution plus
   explicit verified-inherited records keyed by unchanged blob, input hash,
   partition signature, prior result IDs, base report, and archive identity.
   Absolute historical checkout paths are never portable identity.
7. Reload persisted Lance state, validate the complete target inventory, require
   every expected symbol/edge identity, prove deleted/renamed rows absent, and
   only then publish the target archive for the next case.
8. Record selection/verification/injection, update, readiness, and archive time;
   changed/invalidated counts; and LSP work inherited versus executed.

**Feasibility verdict:** CONTINUE. The required mechanisms exist or have clear
extension seams. If verifier-bound inheritance, impact closure, strict deletion,
and the requested regressions cannot be completed, abort before restarting N=70
rather than report a copied-cache shortcut as compliant.

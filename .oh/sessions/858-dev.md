# Issue #858 Development Session

## Aim

Coding agents receive useful, deterministic, task-relevant repository context within the requested byte/token budget when candidates exist, so RNA credibly replaces some source discovery and navigation rather than merely returning compact output.

## Problem Statement

**Current framing:** The task and flat renderers error when fixed or non-body metadata exceeds the caller's budget.

**Reframed as:** Coding agents need an actionable final repository-context packet whose task obligations, evidence quality, degradation policy, byte/token accounting, and hydration path all fit one feasible delivery contract. Today selection can pre-fail on metadata the renderer could omit, while renderer-only compaction can preserve nominal role labels around punctuation constants, incomplete spans, unrelated neighbors, and generic fixtures that do not help implement the task.

**The shift:** Success is not disappearance of `BundleCostExceedsBudget` and `BudgetTooSmall`; success is useful final-packet evidence within budget that credibly displaces repository discovery/navigation.

### Constraints

- **Hard:** Issue #858 acceptance criteria are authoritative.
- **Hard:** Start from current `main`, including merged PR #822.
- **Hard:** Preserve deterministic ranking/rendering, final self-inclusive UTF-8 byte and estimated-token accounting, stable hydration handles, projection semantics, and the shared CLI/MCP service seam.
- **Hard:** Treat bounded task selection and rendering as one delivery contract.
- **Hard:** Final cattrs coverage must include actionable evidence for override/`AttributeOverride`, attrs/dataclass generation, TypedDict generation including `NotRequired[Annotated[...]]`, dict-style NamedTuple generation, precedence/effective `.overrides`, and relevant tests.
- **Hard:** Final delivery verification uses a warmed repository through a real Codex App Server MCP client and records the exact request, index counts, response size, selected paths/symbols, and handles.
- **Hard:** The matched trial uses identical user prompts, injects RNA output separately as model-visible context, contains no filesystem-tool steering, and reports correctness separately from repository exploration.
- **Soft:** Internal selector/renderer types and degradation stages may change if the public delivery semantics remain stable.

### What this framing enables

It permits redesigning the selection/render boundary around a shared feasible envelope, evidence-quality-aware obligation satisfaction, and post-degradation coverage checks rather than separately patching two error exits.

### What this framing excludes

- Renderer-only truncation that retains non-actionable records.
- Role completeness inferred only before rendering.
- Broad embedding or LSP redesign.
- Hardcoding one cattrs ranking order instead of asserting actionable obligation coverage.

## Solution Space

**Updated:** 2026-08-02T16:48:11Z

### Solution Space Analysis

**Problem:** RNA currently treats task selection and rendering as separate successes: selection can pre-fail on metadata that rendering could omit, while rendering can fit a nominally role-complete packet whose records do not provide actionable evidence for the task.

**Key constraint:** The final self-accounted UTF-8 byte/token-bounded packet is the product. It must preserve deterministic ranking/projection semantics, cover the task's actionable obligations, and expose stable hydration paths through the shared CLI/MCP service seam.

**Success:** For budgets at or above a documented minimal envelope, candidates produce a deterministic packet that fits both limits, retains actionable evidence or a compact source handle, and satisfies obligations in the *rendered* packet. The cattrs query must cover its implementation seams and tests without hardcoding one ranking order.

#### Situated knowledge and hard constraints

- Relevant metis surfaced by RNA: `.oh/metis/working-set-selection-must-preserve-causal-paths.md` says a bounded assembler should prefer confident production roots, retain records on relevant structural paths, and abstain without a sufficiently confident production root. **Weight: keep as a design clue, not efficacy evidence**, exactly as that metis cautions. It supports penalizing unrelated neighbors and preserving causal branches, but does not by itself validate replacement behavior.
- `computed-but-not-delivered` applies directly: obligation and quality metadata are useful only if they survive into the rendered MCP packet and its verification, not merely an internal selector state.
- Determinism, final self-inclusive byte/token accounting, stable handles, projection semantics, and the shared service seam are non-negotiable. The design must reuse canonical sort/tie-break rules and avoid CLI/MCP-specific policy.
- `working-set-selection-must-preserve-causal-paths` does not justify indiscriminate graph expansion. Confirmed structural provenance plus task affinity is required before a neighbor can satisfy an obligation.

### Candidates Considered

| Option | Level | Approach | Main trade-off |
|---|---|---|---|
| A. More renderer shrink stages | Band-Aid | Extend `render_projection` to omit capabilities, relationships, metadata, and low-ranked records until it fits. | Removes the visible errors but can make the misleading four-record packet look successful. |
| B. Selector reserve plus render/reselect loop | Local Optimum | Reserve a guessed metadata allowance, score candidate quality, render, then repeatedly reselect after renderer omissions. | Two policy owners and iterative coordination can drift, oscillate, or account differently. |
| C. Shared delivery envelope with quality-bearing evidence units | Reframe | Make deterministic render fitting the selector's feasibility/cost oracle; select only evidence units whose compact floor is actionable, then validate obligations on the winning rendered plan. | Moderate cross-module change and more explicit selection metadata. |
| D. Replace task selection and projection with one global packet optimizer | Redesign | Build a new optimizer over every field, record, span, relationship, obligation, byte, and token. | Highest conceptual purity, but large state space and unnecessary risk to shipped ranking/projection behavior. |

### Evaluation

**Option A: More renderer shrink stages**

- Solves the stated problem: **No.** It handles fixed/non-body overflow but not actionable selection or final obligation coverage.
- Implementation cost: Low.
- Maintenance burden: Medium; each new section adds another ad hoc shrink rule.
- Second-order effects: Converts a diagnosable hard error into compact misinformation; may drop the only useful record after pre-render role completion.
- Optionality: Low.

**Option B: Selector reserve plus render/reselect loop**

- Solves the stated problem: Partially. Quality scoring helps, and retrying can eventually fit.
- Implementation cost: Medium.
- Maintenance burden: High. The selector owns an approximate reserve while the renderer owns actual costs and omissions.
- Second-order effects: Nonlinear coalesced spans and self-inclusive footer accounting make reserves stale; retries complicate determinism and can invalidate previously satisfied roles.
- Optionality: Medium, but it entrenches the split responsible for the defect.

**Option C: Shared delivery envelope with quality-bearing evidence units**

- Solves the stated problem: **Yes.** Feasibility is determined by the same render plan and degradation policy that produces the response, and coverage is read from the fitted final plan.
- Implementation cost: Medium.
- Maintenance burden: Medium-low. There is one delivery contract and one deterministic degradation ladder.
- Second-order effects: The selector must carry explicit evidence quality and obligation keys; render fitting is called during bounded Pareto exploration, so memoization by canonical selected-ID set is important.
- Optionality: High. The same envelope supports flat and task projections, future compact projections, and delivery diagnostics without changing adapters.

**Option D: Global packet optimizer**

- Solves the stated problem: Yes in principle.
- Implementation cost: High.
- Maintenance burden: High; every new render field changes optimizer state and dominance rules.
- Second-order effects: Risks Pareto explosion, opaque choices, and ranking semantic changes. It is disproportionate when the current bounded selector and renderer can share an exact oracle.
- Optionality: High eventually, but poor near-term safety.

### Recommendation

**Selected:** Option C — Shared delivery envelope with quality-bearing evidence units  
**Level:** Reframe

Treat a selected record as a **delivery unit**, not as a role label. A delivery unit has:

1. canonical identity, rank, source anchor, roles/lanes/facets, and acquisition provenance;
2. deterministic evidence quality (`rejected`, `supporting`, or `actionable` plus reason codes);
3. provenance-backed task-obligation keys it can satisfy; and
4. a compact floor: minimal record identity/span plus a resolvable compact hydration handle.

The task selector may include supporting evidence, but only actionable units satisfy required roles or task obligations. The renderer owns one deterministic `fit` operation that returns the exact fitted `RenderedResponse`/`ProjectionPlan`, final accounting, retained delivery units, degradation tier, and compact omissions. The selector's cost/feasibility oracle calls that operation for a canonical selected-ID set under the caller's real byte and token limits. Cache those results. The winning fitted response is returned directly rather than materializing and rendering the selection again.

This makes `bundle_cost(&[])` non-fatal when verbose empty metadata is degradable: the empty plan is first fitted to its compact floor. A candidate set is feasible only when the fitted result remains within both limits and retains its protected actionable units/handles. `BundleCostExceedsBudget` or `BudgetTooSmall` remains valid only below the documented minimal envelope or when no actionable candidate can be represented—not because optional server-owned verbosity was retained.

#### Evidence quality and obligation model

- Reject generated/string constants whose hydrated span is punctuation-only or contains no usable identifier/syntax. The observed `typeddicts.py:438` body `)` cannot satisfy definition/API state.
- Treat zero/tiny/incomplete spans as supporting at best unless a complete declaration/signature or exact source anchor makes them independently actionable. Length alone is not a ban: a short complete function signature can remain actionable.
- A graph neighbor can satisfy dependency/impact only when its edge provenance is sufficiently strong *and* it has task affinity or lies on a relevant structural path from an actionable production root. A confirmed edge by itself does not make the unrelated `impl` decorator relevant.
- A test candidate satisfies the test obligation only when it is a test case/fixture with task-term or structural affinity to an actionable production seam. A generic `TypedDict A` fixture alone is supporting, not coverage.
- Preserve current rank as the primary acquisition signal among equally qualified candidates. Add quality/obligation eligibility before coverage masks, then use stable identity as the final tie-break. Do not use nondeterministic floating thresholds.
- Derive obligation keys generically from normalized query concepts, exact references, high-confidence retrieval roots, and distinct confirmed structural branches. They are not cattrs-specific strings. A candidate may cover several obligations; roles/lanes alone are no longer the entire coverage universe.
- Compute the final coverage certificate from `RenderedResponse.plan.records` and their retained compact floors. If degradation removes the last actionable carrier for an obligation, that fitted set is infeasible and the selector must consider another Pareto state. Pre-render candidate recall is diagnostic only.

#### Deterministic degradation contract

Apply the same documented stages to flat and task projections, with stable rank/identity ordering inside every stage:

1. Compact capability diagnostics and candidate-audit detail into state/reason counts.
2. Remove verbose per-record scoring/evidence diagnostics while preserving selection identity, source span, role/obligation certificate, and a compact handle.
3. Reduce relationships to confirmed edges incident to retained records, then replace lower-value relationship detail with omission counts/handles.
4. Degrade source bodies by lowest marginal obligation value and lowest rank: requested body -> focused span -> signature/minified span -> compact source handle. Preserve at least one actionable focused span when its cost fits.
5. Drop the lowest-ranked/marginal delivery units only when all protected obligations remain covered; report deterministic compact omissions.
6. Emit the minimal envelope: bounded header, at least one actionable identity/span or source handle when candidates exist and budget permits, compact omission summary, and self-inclusive accounting.

At every stage render and recalculate the final footer until both byte and token limits converge. The final reported accounting remains the canonical rendered accounting, never an additive estimate. The documented minimal envelope is the measured maximum of the empty compact scaffold and one compact actionable delivery unit with its accounting footer; tests freeze its semantics without freezing one incidental byte count forever.

#### Compact hydration handles

Keep v1 handles readable for compatibility, but render a v2 compact form for omitted detail. A feasible form is a version/kind prefix plus a deterministic digest of canonical repository-root identity, stable node identity, source range/content hash (or evidence capsule key). Resolution uses the warmed graph/evidence cache, verifies the full identity and collision before returning content, and fails closed on mismatch. This remains repo-native and stable across repeated rendering; it avoids serializing the full current payload in every result. The compact floor must always carry a source handle for actionable records whose body was degraded, and an evidence handle only when evidence hydration is actually available.

### Implementation Notes

- `src/service/search/task_context.rs`: extend `EvidenceCandidate` with evidence-quality reason codes and obligation keys. Make role/lane/facet/obligation masks count only actionable evidence. Preserve the bounded exact Pareto frontier, canonical candidate order, per-file limits, and stable comparison; include obligation coverage and quality in state dominance.
- `src/service/search.rs`: replace the unbounded `rendered_task_bundle_cost` byte-only callback with a memoized delivery oracle that materializes a `ProjectionPlan`, calls the real bounded fitter, and returns feasibility, retained IDs, final coverage, and exact byte/token accounting. Keep orchestration here so CLI and MCP continue to delegate through the same service path. Return the cached winning rendered response rather than rebuilding it.
- `src/service/search/model.rs` / `projection.rs`: represent quality, obligation certificates, degradation state, compact handle aliases, and protected compact floors in the plan. Keep serialization deterministic and backward-compatible where persisted plans require it.
- `src/service/search/render.rs`: centralize the degradation ladder in a monotonic fitter. Every step must strictly reduce a lexicographically defined verbosity state or record count, preventing retry loops. Flat mode uses the same fitter without task obligations; task mode supplies protected actionable obligations.
- Documentation: describe the minimal supported envelope, exact degradation order, what may be omitted, compact hydration recovery, and that both caller limits apply to the entire self-accounted response.

### Why not the alternatives

- Option A fails the core negative regression: it would accept the 2,748-byte misleading simulation.
- Option B keeps two cost models and makes final coverage a retry side effect; this is the intricate Local Optimum coordination the issue exposes.
- Option D is a broader optimizer rewrite than required and risks state explosion and ranking drift.

### Accepted trade-offs

- Candidate construction and plans carry more explicit metadata, although the public compact packet carries less verbosity.
- Exact render fitting during Pareto selection costs CPU; canonical selected-ID memoization and the existing candidate/state bounds keep it feasible.
- The minimal envelope is intentionally not zero: below it the server returns a typed, documented insufficiency rather than pretending an empty or misleading packet is useful.

### Local-maximum check

The obvious renderer-only change was considered and rejected because it optimizes packet size while preserving the wrong success criterion. A full optimizer redesign was also considered and rejected as disproportionate. The recommendation changes the ownership boundary—one fitted delivery contract—without discarding the shipped exact selector, renderer accounting, or service seam.

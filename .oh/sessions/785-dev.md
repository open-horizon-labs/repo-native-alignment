# Issue #785 — hermetic frozen-cohort LSP toolchain

## Aim

**Aim:** Benchmark operators can qualify every frozen N=70 checkout's relevant files through RNA's fail-closed LSP readiness gate without host drift or network access.

**Current State:** The completeness gate can identify unsupported, missing, degraded, or stale files, but server discovery still depends on ambient executables and no sealed cohort-derived toolchain proves all required languages offline.

**Desired State:** A fresh macOS arm64 guest installs an exact, licensed, digest-verified toolchain from a prefilled cache, and all 70 frozen checkouts reach complete per-file readiness with reproducible timing and coverage evidence.

### Mechanism

**Change:** Derive the authoritative extension/server inventory from the frozen population, define one closed lock manifest, provision only digest-verified cache entries, verify RNA descriptor parity, and retain offline per-checkout plus aggregate qualification evidence.

**Hypothesis:** Binding inventory, descriptors, cached artifacts, runtime probes, and readiness reports to explicit digests removes both ambient-PATH drift and silent extension exclusion.

**Assumptions:** The frozen checkout sources are obtainable before network isolation; each included extension has a viable arm64-compatible server/runtime; Tart can provide the fresh-guest isolation proof on the qualification host.

### Feedback

**Signal:** The offline qualifier reports the exact 70 frozen identities, zero friction statuses, all locked server probes/capabilities/quiescence checks passing, and an aggregate seal reproducible from retained evidence.

**Timeframe:** At issue qualification, before #786 release-bundle work or any paid benchmark call.

### Guardrails

- Do not remove, ignore, relabel, or weaken inventory entries to make readiness pass.
- Do not depend on Homebrew latest, unpinned package resolution, ambient PATH, or outbound networking after cache acquisition.
- Keep embeddings, reranking, model/API calls, credentials, protocol/population changes, and #786+ scope out of this issue.
- Preserve the repo-native, computed-but-not-delivered, and CI-artifact release rules.

## Problem Statement

**Current framing:** Install the language servers likely needed by a mostly-Python benchmark.

**Reframed as:** Benchmark operators need every relevant file in the exact frozen N=70 population to produce complete, persisted LSP evidence, but server discovery, runtime resolution, descriptor coverage, and qualification are not yet bound to one offline-verifiable artifact set.

**The shift:** From a convenience install script to a cohort-derived supply-chain and delivery proof.

### Constraints

- **Hard:** Frozen population, fail-closed inventory, exact locks/digests/licenses, macOS arm64 offline operation, descriptor parity, zero friction statuses.
- **Soft:** Packaging layout and implementation language of the provision/qualification tools.

### What this framing enables

One closed contract can drive acquisition, cache verification, installation, probes, descriptor drift tests, per-checkout readiness, timing retention, and aggregate sealing.

### What this framing excludes

Ambient package managers, floating versions, partial language support, inventory suppression, or treating successful process startup as readiness.

## Solution Space

### Candidates Considered

| Option | Level | Approach | Trade-off |
|---|---|---|---|
| A | Band-Aid | Document manual installs for expected Python/docs servers | Cannot prove exact inventory, versions, cache, or offline behavior |
| B | Local Optimum | Add pinned install commands per known RNA descriptor | Still duplicates inventory/descriptor truth and risks transitive drift |
| C | Reframe | One closed cohort-derived lock plus cache/provision/probe/readiness verifier | More validation code and metadata, but every gate shares one contract |
| D | Redesign | Vendor a complete guest image as the only toolchain artifact | Large opaque artifact, weak auditability, and crosses into #786 release bundling |

### Recommendation

**Selected:** Option C — closed cohort-derived toolchain contract

**Level:** Reframe

**Rationale:** The failure mode is not lack of an installer; it is multiple unbound truths. A canonical manifest and deterministic verifier can fail on inventory drift, descriptor mismatch, absent cache entries, executable/package digest changes, missing licenses, failed capabilities, non-quiescence, or non-complete readiness while producing release-manifest-ready evidence.

**Accepted trade-offs:**

- Cache acquisition remains a separate network-enabled phase and must retain provenance/digests.
- Qualification can be expensive because all 70 exact checkouts and every required server must run.
- Any extension without a viable server becomes a visible issue blocker.

### Implementation Notes

- Keep the lock closed-schema and deterministic; make manifest sealing reproducible.
- Derive required extensions from checkout bytes and compare them to both locked servers and RNA built-in descriptors.
- Separate acquire, verify/provision, probe, and qualify modes so offline enforcement is testable.
- Retain per-checkout reports, server timing/capability receipts, aggregate report, and digest inventory.
- CI should use fixtures for drift/cache/descriptor tests; macOS arm64 qualification supplies the real Tart evidence.

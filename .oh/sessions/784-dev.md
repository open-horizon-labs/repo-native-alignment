# Issue #784 — per-file LSP completeness

## Aim

Benchmark operators block model access unless every admitted file in a frozen checkout has durable, snapshot-matched evidence of deterministic LSP processing.

## Problem space and statement

Current language/job aggregates can hide skipped files, processed-zero files, stale reports, and missing expected outputs. The hard boundaries are the frozen N=70 cohort, no model spend, no server provisioning, explicit exclusions only, deterministic output, and fail-closed lifecycle/persistence checks.

## Chosen solution

Add a role-aware deterministic inventory and snapshot-bound per-file report, persist it beside the graph cache, validate it through one machine-readable pre-model CLI command, and aggregate that command over the frozen cohort. Missing fleet components remain visible blockers for #785.

## Consolidated implementation review

The batch stayed at the existing persistence seams: the Git-index inventory, durable LSP work-item ledger, persisted graph, full-scan CLI, and verbose MCP readiness. It did not add another scheduler, provision servers, or touch the benchmark executor.

Review fixes applied before commit:

- completed LSP response output no longer counts as persisted graph output; emitted edge IDs must be present in the persisted graph;
- a skipped work item cannot hide behind another completed work item for the same file;
- crash, timeout, cancellation, and stale lifecycle failures retain distinct terminal states;
- aggregate readiness requires 70 distinct checkout identities and rejects business-context-enabled reports;
- MCP readiness revalidates checkout/config/policy/schema/work-generation compatibility instead of presenting a stale report as ready; and
- ordinary full scans do not pay the benchmark-report cost; report construction and enforcement run only in disabled benchmark mode.

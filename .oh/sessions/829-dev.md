# Issue #829 development session

## Problem statement

Full-inventory readiness must derive Markdown work from the operations that the
locked descriptor schedules and the server negotiates, preserve authenticated
recovery evidence, and route `Dockerfile`/`Dockerfile.*` consistently without
weakening fail-closed persistence or provenance checks.

Acceptance is defined by GitHub issue #829 and draft PR #831. In particular,
missing or discarded required evidence must still block READY, and retained
failed caches must never be rebound to a new producer.

## Chosen solution

- Build capability-aware scheduled-operation evidence and validate it against
  negotiated server capabilities.
- Authenticate recovered work against the current scan/recovery execution
  identity rather than admitting timestamp-adjacent historical records.
- Retire an obsolete operation only when the same graph node is still present
  in the current scheduled work; retain vanished-node unmatched work as a
  fail-closed audit record.
- Classify `Dockerfile` and `Dockerfile.*` before generic extension routing in
  both the Rust and Python inventory implementations.

## Execute

**Status:** focused implementation and retained-state proof complete

The consolidated implementation is pushed on `issue/829`. The current
follow-up corrects recovery-ledger handling for an operation removed from a
still-current node while preserving the existing vanished-node failure path.
It also keeps carried audit-record persistence keys aligned with their item
IDs. Final remediation routes deterministic Dockerfile names to the exact
pinned Dockerfile LSP rather than the generic config server. The frozen
inventory now includes a dedicated `dockerfile` partition while Dockerfiles
retain their config role.
